# P166 SM4 One-Loop Unification Audit

## Question and Positive Deliverable

P166 must reproduce and independently adjudicate SM4's fixed-reference
one-loop running and three pairwise crossings. The positive deliverable is an
accepted exact composition or a genuinely new reusable ledger that completely
classifies the common-intersection question, the crossing spread, and their
input and convention boundaries, then terminally disposes SM4. A broad window,
near-miss, no-go, or failed common intersection alone does not complete P166.

## Invariants, Conventions, and Allowed Imports

C-RGE-004 exactly classifies signed-affine inverse-coupling intersections,
pairwise crossings, rank degeneracies, reference shifts, and paired Abelian
coordinate rescaling. C-RGE-005 conditionally supplies the exact vector
`(41/10,-19/6,-7)` for a declared normalized representation table. C-RGE-006
does not upgrade SM4's fixed-data one-loop test into two-loop physical running.

The source convention must be mapped explicitly to the canonical affine sign.
Fixed low-scale coordinates, three pairwise crossing scales, their absolute
spread, and one common intersection are separate objects. Thresholds,
matching, scheme conversion, uncertainties, perturbative-domain control,
global group and U1 normalization, boundary provenance, observations, and a
substrate mechanism remain excluded unless separately governed.

## Selection Criteria and Blinding

Selection is ordered by accepted dependency closure, exact sign and
normalization consistency, exact common-intersection rank before a numerical
spread summary, comparator separation, assumption and parameter economy, API
nonduplication, mutation sensitivity, reference and Abelian covariance, and
explicit threshold, scheme, and perturbative boundaries. Numerical proximity
or a familiar energy scale cannot select a concept. Prior exposure is recorded
and no fresh blinding is claimed.

## Implementation and Oracle Plan

SymPy exact rationals fit the affine equations, augmented rank, pairwise
crossings, sign map, reference covariance, normalization transforms, and
threshold-offset counterfamilies. Floating evaluation is regression coverage
for the supplied decimal readings and plotted scales, never the oracle for
common intersection. The primary route will use accepted canonical APIs where
their scope matches; an independent route will construct the lines and ranks
without importing them.

Mutations include each coefficient and boundary coordinate, the beta sign,
reference scale, U1 coordinate normalization, equal and repeated slopes, and
independent sector offsets. Source-graph replay will count lexical checks,
runtime checks, and assertions separately. Compatibility preflight checks
direct, imported, dynamic, and eager legacy NumPy access. Canonical integration
uses `trapezoid_integral`; mutable scripts use `np.trapezoid`; an immutable
version-only abort receives an isolated alias backed by `np.trapezoid` before
scientific adjudication and never counts as candidate failure.

## Review and Promotion Plan

Every distinct SM4 claim receives an individual verdict. Accepted composition
requires primary and independent exact routes, source and dependency audit,
nonduplication, consumer and compatibility replay, materialized adjudication,
and a terminal qualified or other disposition with evidence paths. A new API
or claim additionally requires impact analysis, focused tests, release update,
generated documentation, and accepted-memory synchronization. Validation and
commit are separate process invocations, and any final attempt is finalized
after the unchanged integrated gate rather than triggering another full suite.

## Done Gate

P166 closes only when a positive exact composition or novel importable object
exists, every source predicate is adjudicated, the common-intersection and
spread statements have sensitive oracles, all inputs and omissions are typed,
consumers replay, governance agrees, and debt is empty. An honest near-miss or
failure to unify is attempt evidence, not the requested completion.
