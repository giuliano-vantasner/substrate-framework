# P224 MR6 Ledger and Confrontation Audit

## Question and Positive Deliverable

P224 must decide whether MR6 adds a distinct theorem or numeric result beyond
the individually adjudicated MK and MR campaigns and whether its correction
ledger is complete, convention-correct, dependency-closed, and current. The
positive object is a claim-level authority, formula, truth-value, parameter,
consumer, and global-closure ledger; rejecting source chronology alone is not
completion.

## Base Release and Provenance

The base is v0.159.0 at clean commit `1468b13`, with 202 accepted claims and
one pending unit. MR6 is pinned at substrate commit `6d1f4e0`, SHA-256
`944337...d2106d9d`, 22,028 bytes, and 394 lines; its tracked path is clean. The
generated queue exposes six checks, three assertions, mixed symbolic/numeric
scope, a four-overturn count, the pi-squared correction, and one approximate
mass value, but not the remaining source body.

## Invariants, Conventions, and Allowed Imports

The accepted registry and adjudicated campaigns outrank MR6's later summary.
C-BPS-001 and C-VEC-002 own the normalized-current bound and lambda conversion;
C-BPS-002/003 retain attainment and remainder ceilings; C-GSK-001 and
C-RDIFF-001 own conditional radial and signed-difference algebra; C-VAR-002/003
own only common-domain infimum theorems. Every earlier MK/MR source is terminal.

## Candidate Preregistration

Eight routes are frozen before the MR6 body or execution: authoritative ledger
reconstruction, exact convention conversion, structural/numeric separation,
current numeric replay, provenance-only overturn typing, completeness-guard
audit, duplicate-only closure, and terminal global synchronization. Selection
ranks accepted authority, exact convention, novelty, dependency closure,
mutation sensitivity, and physical typing before remaining values.

## Selection Criteria and Blinding

Ledger rows are selected only by their source predicates and accepted claim
closure. The number of source checks overturned, agreement with a mass, or
proximity to a comparator cannot select a concept or promote a claim.

## Proposed Claim Delta

The freeze reserves no identifier. A claim is possible only if MR6 contains a
new theorem or reproducible numeric object not already owned by the accepted
registry and with a consumer beyond historical bookkeeping. A corrected source
truth value or summary row alone earns no claim or package API.

## Implementation and Oracle Plan

SymPy and canonical BPS APIs will verify every convention conversion and
conditional value. The verifier will enumerate all six predicates and three
assertions, compare every ledger row with immutable adjudications, distinguish
structural invariance from parameter-dependent numbers, mutate normalization
and row membership, and test the guard against actual data flow. A fresh review
will independently derive the load-bearing algebra without importing MR6.
MR6's sampled integration preflight uses current `trapezoid`; version-only
events remain compatibility provenance and never scientific failures.

## Attempts and Continuation

Attempt 0001 freezes eight candidates, no claim identifier, exact convention
surfaces, row and parameter mutations, provenance, and compatibility policy.
Memory recall finds prior MR6 consumer records but no direct ledger-
confrontation entry; reused statements were verified at accepted campaign
sources. A pre-freeze module read used the nonexistent name
`variational_composition.py`; registry search repaired it to `variational.py`
and the actual module was read in full before source inspection.

Attempt 0002 opens MR6 after the committed freeze and reuses P215's
hash-identical clean six-check execution. Exact audit retains the pi-squared
formula ratio, common-scale coefficient map, pointwise nonnegative additions,
and only a nonstrict infimum order already owned by accepted claims. Most
ledger rows and the count of four occur only in check prose; the MK6.3 proxy
tests comparator thresholds rather than double counting. The confrontation is
stale after P223, five samples do not prove continuous monotonicity, stationary
branches are not minima, positivity somewhere does not prove a strict infimum
gap, and the guard omits all solved values while comparators drive several pass
predicates.

Attempt 0003 preserves the first primary-verifier stop after six passes. A
manually transcribed corrected BPS decimal differed from direct 30-digit SymPy
evaluation. Replacing only that expected decimal with `99.41652889533228`
repairs the implementation check; the exact expression and `1e-12` tolerance
are unchanged.

Attempt 0004 preserves the fresh review's stop after ten passes. Its raw search
for the short identifier `bs` collided with the characters inside `abs`.
Replacing substring matching with exact AST names from the `indep` assignment
repairs and strengthens the data-flow oracle without changing the verdict.

Attempt 0005 passes 21 primary checks, 12 fresh independent checks, eight final
source-graph checks, and 88 focused canonical tests. Zero accepted claims
change. Exact pi-squared normalization and the rank-one common-scale path
survive; finite counterexamples restrict the variational conclusion to the
nonstrict order already owned by C-VAR-002. Canonical values bound the stale
source context, but no claim, API, test, or release change is warranted.

## Review and Promotion Plan

Every source predicate receives an individual four-axis review. A distinct
claim requires nonduplicate reach, accepted inputs, a sensitive oracle, fresh
review, consumers, release synchronization, and a proportional integrated
gate. Otherwise the terminal decision names exact owners and durable evidence,
then closes the source queue without altering accepted science.

## Done Gate

P224 closes only when MR6 and every in-scope source unit are terminal, the
positive ledger exists, all affected consumers and generated records agree,
the framework debt ledger is empty, and no compatibility ceremony is confused
with a scientific oracle.
