# P219 MK6 Confrontation and Tension Audit

## Question and Positive Deliverable

P219 must construct a convention-safe exact ledger for MK6's BPS,
shared-functional, and signed-difference statements and determine which have
accepted dependency closure. The positive deliverable is a reusable exact
shared-functional theorem if novel, plus a terminal MK6 disposition. Rejecting
a physical mass or double-counting story alone does not complete the campaign.

## Base Release and Provenance

The base is v0.157.0 at clean framework commit `af46446e`, with 200 accepted
claims and six pending source units. MK6 is pinned at substrate commit
`6d1f4e0`, SHA-256 `ef900954...81788`, and 18,971 bytes; that source file is
clean while unrelated source-repository changes are excluded. The generated
queue exposes six checks, one assertion, the claimed 12.34 and 981.2 values,
the pure-pion BPS formula, and the double-counting diagnosis.

## Invariants, Conventions, and Allowed Imports

C-BPS-001 uses `lambda_BPS^2*pi^4*B0^2`; C-VEC-002 requires
`lambda_A=pi^2*lambda_BPS`. C-GSK-001 is one shared-profile functional with
separately supplied coefficients, and C-GSK-002 is only finite-domain numeric
evidence under supplied inputs. C-RDIFF-001/002 do not provide a physical state
or scale map. MK1-MK5 supply no accepted physical coupling closure. These exact
ceilings, plus elementary infimum order for a common admissible set, are the
only permitted inputs.

## Selection Criteria and Blinding

Accepted conventions and dependencies rank first, followed by common
functional/state typing, assumption economy, bound-versus-attainment
distinctions, dimensional normalization, mutation sensitivity, novelty, and
terminal closure. Queue-exposed values cannot be blinded; every remaining
equation, predicate, constant, output, and consumer detail remains unopened
until the validated committed freeze.

## Proposed Claim Delta

P219 provisionally reserves C-VAR-002 for the exact theorem that the infimum of
a finite sum of real functionals on one common nonempty admissible set is at
least the sum of their separate infima, with equality requiring a common
minimizing configuration or the appropriate common minimizing-sequence
condition. It is promoted only if distinct, useful to the joint generalized
functional, independently proved, implemented, tested, and carefully scoped.

## Implementation and Oracle Plan

SymPy and direct order arguments are the strongest oracles for convention
elimination, scale cancellation, signed differences, and finite-functional
inequalities. Counterexamples will use incompatible component minimizers,
bound-without-attainment, and pi-squared mutations. If any unresolved numeric
claim survives, it must use declared precision, equations, domains, solver
status, residuals, isolated refinements, and an independent method; otherwise
MK5 execution evidence is not rerun. Compatibility preflight covers direct,
imported, dynamic, and eager legacy access before one native source run.

## Attempts and Continuation

Attempt 0001 freezes eight candidates, C-VAR-002, exact formula surfaces,
mutations, imports, provenance, compatibility handling, and the honest limits
of comparator blinding. A failed source diagnosis triggers convention repair,
a different variational representation, or duplicate-only qualification; it
does not end the positive framework effort.

## Review and Promotion Plan

Every MK6 predicate and any C-VAR-002 statement receives an individual review.
Promotion requires importable pure APIs, targeted tests, fresh independent
proof, consumer replay, release and generated-state synchronization when a
claim changes, editable-disposition regeneration, and the correctly scoped
integrated gate. Terminal qualification must preserve rejected physical claims
and durable evidence.

## Done Gate

fully promoted or rejected by nonduplication, mutation-sensitive evidence,
every source predicate and consumer adjudicated, synchronized records, and an
empty campaign debt ledger.
