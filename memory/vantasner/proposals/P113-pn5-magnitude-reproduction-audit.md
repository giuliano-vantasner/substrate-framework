# P113 PN5 Magnitude-Reproduction Audit

## Question and Positive Deliverable

This campaign must produce a complete exact adjudication of PN5's energy-count
and toy paired-loss magnitude surfaces. The positive object is an exact,
representation-safe ledger for the declared inputs, quotient plateaus, set
summaries, scale behavior, C-RES-001 specialization, dimensions, and physical
ceiling, together with an independently reproduced route and every source
predicate and consumer reviewed individually.

A demonstration that selected external inputs reproduce named decades is not
the requested success by itself. The campaign completes only when the
scientifically supportable object is mapped to accepted framework authority or
a genuinely distinct claim, PN5 receives a governed terminal disposition, and
all debt is empty.

## Invariants, Conventions, and Allowed Imports

Every energy, detuning, loss, and coupling value remains a declared input with
an exact unit representation. Floor division is Euclidean bookkeeping, not a
quantum process. C-RES-001 supplies only exact finite complex-matrix algebra,
not a bath, probability, rate, nuclear or phonon channel, or material map.
Numerical set overlap is a property of the selected inputs, not their
derivation. Common unit rescaling preserves a quotient and therefore cannot
identify an absolute scale.

Allowed mathematics includes exact integers, rationals, decimal-prefix
definitions, interval inequalities, finite set summaries, elementary
calculus, and dimensions. SymPy is allowed for exact identities and limits;
Fraction and Decimal supply an independent representation route. P110 is
immutable adjudicated evidence for quotient bookkeeping but contributes no
accepted claim. PN5 and named literature may be opened only after freeze and
are evidence, never authority.

The PN4-PN5 source cycle is not an accepted dependency cycle. PN4 is now
qualified through C-RES-001, which PN5 may import at its exact ceiling. PN4's
rejected channel narrative and PN5's prior candidate status supply no premise.

## Selection Criteria and Blinding

Selection is ordered by accepted dependency closure, exact input and unit
provenance, representation safety, correct interval and limit behavior,
mutation sensitivity, physical-ceiling honesty, assumption economy,
nonduplication, and complete consumer closure. Numerical closeness to a named
decade is excluded from concept selection.

before source execution or inspection of its eleven predicate bodies.

## Implementation and Oracle Plan

The primary oracle will hash-pin PN5, count all static and runtime predicates,
reconstruct exact unit conversions, quotient and remainder, inverse plateaus,
threshold jumps, finite-set extrema and set relations, common and independent
scale transformations, and the C-RES-001 pair specialization. It will mutate
binary representation, endpoints, input scales, coupling product, detuning,
loss, and physical interpretation premises. SymPy fits exact rational,
calculus, and limit obligations; no numerical solver or sampled quadrature is
needed.

An independent route will use Fraction, Decimal, scaled integers, and a fresh
derivative of the pair magnitude without importing a new P113 implementation.
Arbitrary-band and arbitrary-target families will distinguish selected-input
overlap from prediction. Zero interaction or absent state/rule countermodels
will keep the counts and toy element while removing any transition rate.

The source graph has two direct consumers, qualified PN4 and pending PN6, and
twenty-two transitive consumers: CM1 through CM7 where reachable, GB1, GB4,
GB6, MD1 through MD6, and WN2 through WN7. Every file will be pinned by hash.
The PN4-PN5 cycle will be recorded explicitly rather than counted as accepted
authority.

Compatibility preflight is mandatory even though no integration is expected.
Canonical sampled work would use `trapezoid_integral`; mutable current scripts
must use `np.trapezoid`; immutable PN5 would receive an alias-only replay only
if removed `np.trapz` were its sole abort. Such a version event would not be a
scientific candidate failure.

The targeted commands are PN5's hash-pinned source run, the primary and
independent exact verifiers, relevant C-RES-001 and P110 replay, repository
schema validation before source inspection, and one full `scripts/validate.sh`
only at a complete terminal boundary. Generated documentation and source
claims will never be hand edited.

durable memory, and the parent effort must agree, and the final gate gets one
integrated run.
