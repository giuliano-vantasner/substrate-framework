# P131 T1Z2 Cross-Oracle Sign Audit

## Question and Positive Deliverable

P131 must reproduce and adjudicate T1Z2's assertion that three minus-one
evaluations are one common C2 object. The positive deliverable is either a
genuinely typed pullback or intertwining theorem beyond the accepted character
classification, or a terminal source mapping that preserves the exact sign
arithmetic while rejecting the unsupported cross-domain identity.

## Base Release and Provenance

The accepted base is v0.100.0 at parent checkpoint `fb8160d`; the latest
scientific transaction is P130 at `bf7a84d`. T1Z2 is pinned to
`substrate@6d1f4e02f87a0bd1dc326cb68af01872d1e88c64`, path
`merged-framework/bridges/phase-1/bridge_T1Z2_same_minus_one.py`, SHA-256
`d9c08f9440fb79b9ef445ad77aff113db6c7c7f8943c5838180fb5704fd71bed`.

The queue exposes ten literal check calls, one assertion, a symbolic oracle,
and dependencies OM1 and S2. OM1 is qualified through C-TOP-001 and C-CHR-001;
S2 remains pending. Reverse candidate consumers are qualified OM1 and AS6.
This metadata is navigation evidence, not authority.

## Invariants, Conventions, and Allowed Imports

C-TOP-001 supplies only integer winding parity. C-CHR-001 supplies the complete
finite cyclic and binary-product sign-character classification and already
proves that matching selected values do not identify functions or source
objects. OM1 has no accepted cross-sector collapse, and pending S2 grants no
hedgehog, baryon, spectrum, rotation, or statistics premise.

Exact finite-group arithmetic, kernels, quotients, and commuting diagrams are
allowed. A common pullback must expose every source domain and quotient map. A
representation equivalence must exhibit an intertwiner and preserve the full
action. A physical identification additionally needs governed state, dynamics,
and spin-statistics data. T1Z2 becomes evidence only after this contract freezes.

## Selection Criteria and Blinding

Selection is ordered by dependency closure, explicit types, full-map equality,
exact group structure, counterexample sensitivity, physical-scope honesty,
parameter economy, and nonduplication. The synopsis already exposes minus-one,
plus-one, and T1Z2's favored conclusion. There is no empirical comparator, but
those exposed values cannot select a theorem or make an identity check pass.

## Proposed Claim Delta

P131 provisionally reserves C-CHR-002 only for a nonduplicate typed pullback or
intertwining theorem with explicit maps and a positive reusable role. If T1Z2
contains only selected evaluations or restates C-CHR-001, no claim or package
API is added and the unit is terminally qualified or marked duplicate evidence.

## Implementation and Oracle Plan

The primary route will hash and parse T1Z2, classify all ten predicates, and
compare every constructed object with accepted definitions. Exact SymPy or
finite truth tables will test the sign arithmetic, full character laws,
kernels, quotient maps, and any claimed commuting square.

The independent route will avoid T1Z2 arithmetic and enumerate competing
source groups or binary-product characters that agree at the selected odd and
even evaluations. C4, independent C2 factors, changed quotient maps,
simply-connected hosts, even charges, trivial characters, and representation
countermodels must break overstrong identity verdicts. An equality test that
only compares a scalar set is not a headline oracle.

The compatibility preflight scans T1Z2 and replayed consumers. Mutable scripts
must use `np.trapezoid` or the canonical integration helper; immutable-source
legacy aliases receive compatibility-only replay and cannot lower a scientific
verdict. This campaign is expected to be exact and require no quadrature.
