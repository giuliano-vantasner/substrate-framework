# P200 MD5 Branching Handshake Audit

## Question and Positive Deliverable

P200 must deliver the strongest exact importable condition governing weighted
two-channel monotonicity when the weight may depend on population. It must
separate that theorem from already accepted constant-weight allocation and
factorial-one arithmetic, then terminally adjudicate MD5's isotope and material
handshake rather than stopping at their rejection.

## Base Release and Provenance

The accepted base is v0.148.0 at framework commit `d5a8125`. MD5 is pinned at
`bcc45611ce87312a11cdc35d2bdc4c1a92b2e9fdb44c427f7676701f69326ecb`
in the immutable predecessor baseline. Its native result was exposed in prior
source graphs, so P200 preserves that exposure and claims no fresh blinding.
Memory search found no authoritative MD5 theorem; reused facts are sourced from
accepted registry entries and canonical modules.

## Invariants and Allowed Imports

C-BRN-001 owns allocation of separately declared common-dimension rates.
C-CMB-003 owns a static mathematical factorial-one mass. C-MKV-001 owns a
separately declared Markov process but supplies no material, isotope, or
branching observable. PN2 has no accepted mapping. A positive mathematical
weight does not create exhaustive physical channels or a rate law. Mutable
numeric code uses `numpy.trapezoid` or the shared helper.

## Candidate Preregistration

Six candidates distinguish the accepted constant case, a general derivative
criterion, a random-weight extension, the source isotope reading, no new claim,
and foundational revision. Candidate selection uses declared dimensions,
exact sign necessity and sufficiency, mutation sensitivity, nonduplication,
and useful reach without physical overclaim. Numerical closeness selects
nothing.

## Proposed Claim Delta

P200 reserves C-BRN-002 for the exact condition
`w(N)+N*w'(N)>0` if it survives independent review and is distinct from
C-BRN-001. Expected dependencies are C-BRN-001 and no material claims;
C-CMB-003 supplies only a constant-positive-weight corollary.

## Implementation and Oracle Plan

Reusable exact allocation derivatives belong in the canonical branching
module with pure APIs and tests. Primary and independent SymPy routes will
check differentiation, signs, counterexamples, limits, dimensions, and
mutations. Source and reverse consumers remain byte-pinned; compatibility
events are handled separately from scientific verdicts.
