# P195 WN7 Honesty Firewall Audit

## Question and Positive Deliverable

P195 must determine whether WN7 establishes a semantically complete honesty
firewall for WN1 through WN6 or only finite pinned-byte predicates. The
positive deliverable is a predicate-complete exact source ledger with tested
semantic ceilings and a justified terminal disposition. If a genuinely new
reusable AST, import, or data-flow object survives, it must be extracted and
tested; documenting scanner weakness alone is not completion.

## Invariants, Conventions, and Allowed Imports

A finite scanner proves only its exact matcher on pinned bytes, paths,
decoding, tags, and scope. P120 and P127 already establish construction,
alias, Unicode, comment, docstring, import, configuration, clamp, data-flow,
and semantic evasions. `audit_source_tokens` is canonical navigation evidence
and explicitly disclaims semantic or scientific dependency proof.

WN1 through WN6 and CM1, GB4, GB6, and PN4 are individually qualified. Only
their accepted mappings carry authority; a passing scanner grants no blanket
promotion. No numerical integration is expected. Mutable quadrature uses
`np.trapezoid` or `trapezoid_integral`, while immutable legacy compatibility
stops remain non-scientific evidence.

## Selection Criteria and Blinding

Selection prioritizes pinned scope and matcher fidelity, novelty beyond P120,
P127, and `audit_source_tokens`, executable syntax and data-flow coverage,
evasion sensitivity, false-positive control, relevance to accepted objects,
dependency authority, assumption economy, and terminal governance fit. A green
tally or absence of selected strings cannot select a scientific concept.

## Proposed Claim Delta

No claim identifier is reserved. Existing governance deliberately keeps
finite scanner results out of the scientific claim registry. A new claim or
API requires a distinct positive object and consumer rather than a larger
campaign-specific token list.

## Implementation and Oracle Plan

The source audit will pin syntax, imports, compatibility, target paths,
encoding, token lists, tag exemptions, assignment matchers, comment handling,
check data flow, local physics fixtures, self-tests, and every headline edge.
Lexical sites, runtime executions, assertions, and target-file predicates will
remain separate inventories.

The primary route will reproduce exact matchers, compare them with AST and
canonical source-audit surfaces, and apply construction, alias, Unicode,
comment, string, tag, assignment, clamp, configuration, imported-value, and
equivalent-formula mutations. The independent route will implement fresh
token/AST classification without importing campaign helpers. Physics guards
will be compared with accepted mathematical objects rather than Boolean
stand-ins. No numerical rerun can strengthen a finite lexical claim.
