# P114 PN6 General Finite-Pair Sum Audit

## Question and Positive Deliverable

This campaign must deliver a complete exact adjudication of the E=0 finite sum
over arbitrary symmetric detuning pairs. The positive object is a convention-
closed sum and block ledger with necessary cancellation and strictness
premises, counterexamples, asymptotics, normalization, independent inversion,
and physical ceiling, mapped without duplication to accepted governance or to
a genuinely distinct claim if one survives.

## Invariants, Conventions, and Allowed Imports

C-RES-001's finite block, resolvent orientation, pair specialization, one-pair
regimes, normalization distinction, and physical ceiling remain fixed. At
zero loss a pair cancels only under matching complex products; a full sum can
also cancel across unequal pairs. Under common positive loss, real
nonnegative products give a strictly negative imaginary sum only if at least
one product is nonzero.

Signed or complex products, zero couplings, unequal pair products, asymmetric
detunings, and nonuniform shifts remain admitted countermodels. Finite sums,
exact rational calculus, and SymPy matrices are allowed. Pending source units
and rejected PN4 or PN5 narratives are forbidden premises.

## Implementation and Oracle Plan

The primary exact oracle will hash-pin PN6, count every runtime predicate, sum
C-RES-001 pairs, invert multiple full blocks, derive strictness and both loss
coefficients, and test zero, signed, complex, asymmetric, nonuniform, scaling,
and stationary-equation countermodels. An independent route will construct
fresh diagonal matrices and rational sums without importing a new P114 API.

No numerical solver or quadrature is needed. Source numeric examples are
regression only when exact algebra already decides them. Canonical integration
would use `trapezoid_integral`, mutable NumPy code must use `np.trapezoid`, and
an immutable `np.trapz`-only abort would receive an alias-only replay rather
than scientific rejection.

The source graph has no downstream consumer, so consumer closure is an empty
set verified from the generated queue. Targeted C-RES-001 tests and exact
campaign oracles precede one integrated terminal workflow boundary.
