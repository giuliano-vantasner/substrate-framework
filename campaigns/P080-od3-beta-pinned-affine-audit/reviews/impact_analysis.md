# P080 Impact Analysis

P080 changes no accepted claim, canonical symbol, package API, release member,
formal theorem, or generated claim document. It adds one campaign consumer of
the existing exact linear-system, scale-constraint, reciprocal-coupling,
scale-provenance, induced-gravity, and gravity-confrontation APIs, then changes
only OD3's authoritative migration disposition and regenerated queue entry.

Direct repository search identifies `diagnose_log_constraints`,
`shift_log_references`, `generalized_least_squares`,
`reciprocal_coupling_ledger`, and `reciprocal_coordinate_change_ledger` as the
reused surfaces. P080 calls them without changing signatures, data classes,
conventions, or semantics. The independent route imports none of those
scientific APIs and rebuilds the affine elimination, nullspace, solve,
reference shift, nuisance rank, baseline derivative, and fixed-coordinate
conjugation directly.

The only generated consumer is `migration/source-claims.yaml`, which must be
regenerated from `migration/dispositions.yaml`. Accepted claim docs, release
manifests, and framework memory must remain byte-current at unchanged
`v0.72.0`. There are no Lean, ODE, PDE, simulation, floating-fit, or numerical
quadrature consumers. The controlling replay is therefore both P080 exact
routes, focused tests for the reused APIs and accepted ceilings, focused
governance/inventory tests, one integrated workflow boundary, and
`git diff --check`.

Direct search at the final boundary found only the expected existing package,
test, and campaign consumers; no canonical definition changed. Both exact
routes pass 36 and 22 checks, respectively, 102 affected canonical tests and
17 focused governance tests pass, and the single integrated workflow passes
all 755 repository tests. Generated docs and accepted memory remain byte-
current at v0.72.0, and `git diff --check` is clean.
